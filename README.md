# Vilgane

Сайт для учёта часов: данные из докладки **GIRITON** переносятся автоматически, к каждому ID вручную
добавляются имя и ставка, ведутся авансы с комментариями. Итог по каждому сотруднику — «к выплате».

```
GIRITON REST API  ──(по расписанию)──▶  Postgres  ──▶  веб-интерфейс (вход по паролю)
       ID, часы                         + имя, ставка, авансы
```

## Что умеет

- **Автоперенос из GIRITON** — раз в час (настраивается) тянутся ID сотрудников, ID карты и часы
  за текущий месяц. Кнопка «Синхронизировать» делает то же вручную для любого месяца.
- **Имена из Google-таблицы** — список сотрудников (`AUR_S05_1009` → ФИО, e-mail, статус)
  подтягивается автоматически вместе с часами и кнопкой «👤 Имена». Достаточно дописать строку
  в таблицу — имя появится на сайте. Статусы «Отпуск» / «Неактивен» показываются бейджем.
- **Имя к каждому ID** — вписывается прямо в таблице, сохраняется по выходу из поля.
  Ручная правка закрепляет имя: таблица его больше не перезапишет. Очистили поле —
  имя снова берётся из таблицы.
- **Ставка Kč/ч** — тоже правится в таблице; «Начислено» = часы × ставка.
- **Авансы** — клик по ячейке «Авансы» открывает панель: сумма, дата, комментарий; список
  всех авансов месяца, любой можно удалить.
- **К выплате** = начислено − авансы. Итоги по месяцу сверху, выгрузка в CSV.
- **Вход по паролю** — без него не видно ничего, включая таблицу.
- **Настройка на самом сайте** — токен GIRITON, ссылка на таблицу, показатель часов и
  интервал синхронизации правятся в ⚙ «Настройки». Токен наружу не отдаётся: в интерфейсе
  видны только последние 4 символа.

## Переменные окружения

Обязательна ровно одна: **`DATABASE_URL`**. Всё остальное настраивается на самом сайте
(кнопка ⚙ «Настройки») и хранится в базе, поэтому в панели хостинга ничего вписывать не нужно.

Пароль администратора генерируется при первом запуске и печатается в лог сервиса:

```
────────────────────────────────────────────────────
  ПАРОЛЬ ДЛЯ ПЕРВОГО ВХОДА: gWS48kjWrk9w
  Смените его на сайте: Настройки → Пароль
────────────────────────────────────────────────────
```

Переменные ниже необязательны. Если задать любую из них, она **жёстко перекрывает**
настройку с сайта, и соответствующее поле становится недоступным для правки.

| Переменная | Назначение |
|---|---|
| `ADMIN_PASSWORD` | фиксирует пароль, отключает его смену на сайте |
| `SESSION_SECRET` | подпись сессионной куки; иначе генерируется сам и хранится в базе |
| `GIRITON_API_TOKEN` | токен GIRITON REST API, формат `firma.xxxx-xxxx-xxxx-xxxx` |
| `GIRITON_ACTIVITY` | показатель, считающийся часами (по умолчанию `Práce (celkem)`) |
| `NAMES_SHEET_URL` | ссылка на Google-таблицу со списком сотрудников |
| `SYNC_INTERVAL_MINUTES` | период автосинхронизации, `0` — выключить (по умолчанию 60) |
| `CRON_SECRET` | ключ для внешнего планировщика: `GET /api/cron/sync?key=...` |

### Где взять токен GIRITON

В веб-приложении GIRITON: **Nastavení → Spárovaná zařízení → REST API token**.
Токен постоянный, перелогинов не требует. Логин и пароль от GIRITON приложению не нужны —
и хранить их здесь не нужно.

### Таблица со списком сотрудников

Подойдёт обычная ссылка «Поделиться» — приложение само приведёт её к CSV-выгрузке.
Доступ у таблицы должен быть **«Просматривать могут все, у кого есть ссылка»**.

Колонки ищутся по названиям, порядок и лишние столбцы значения не имеют:

| Ищем | Подходящие заголовки |
|---|---|
| номер | `Складской номер`, `Табельный номер`, `ID`, `Номер` |
| имя | `ФИО сотрудника` либо пара `Имя` + `Фамилия` |
| почта | `Рабочий e-mail`, `E-mail`, `Почта` |
| статус | `Статус` |

Номер вида `AUR_S05_1009` разбирается на карту `AUR_S05` и ID `1009`, поэтому сопоставление
с GIRITON работает независимо от того, какой из двух форматов он отдаёт.

> Ссылка на таблицу **не хранится в репозитории**: он публичный, а в таблице ФИО и рабочие
> адреса сотрудников. Она вводится на сайте и лежит в базе.

## Развёртывание на Render (рекомендуется)

1. Render → **New → Blueprint** → выбрать этот репозиторий → **Apply**.
   Подхватится `render.yaml`: веб-сервис + бесплатный Postgres. Заполнять поля не нужно.
2. Открыть вкладку **Logs** сервиса и скопировать пароль из рамки «ПАРОЛЬ ДЛЯ ПЕРВОГО ВХОДА».
3. Открыть выданный адрес, войти этим паролем.
4. ⚙ **Настройки** → вставить токен GIRITON и ссылку на таблицу → «Сохранить».
5. **Синхронизировать**. Дальше данные обновляются сами раз в час.

Пароль стоит сразу сменить там же, в «Настройках».

Приложение — обычный Node/Express, поэтому так же разворачивается на Railway, Fly.io или любом VPS:
нужны только Node 20+, Postgres и переменные окружения. Схема БД применяется автоматически при старте.

> На бесплатном плане Render сервис засыпает без трафика — автосинхронизация в это время не идёт.
> Чтобы данные обновлялись независимо от сна, повесьте внешний планировщик (например cron-job.org)
> на `https://<адрес>/api/cron/sync?key=<CRON_SECRET>`.

## Локальный запуск

```bash
npm install
cp .env.example .env      # достаточно указать DATABASE_URL
npm start                 # http://localhost:3000, пароль — в выводе консоли
```

## API

Всё под `/api`, кроме входа требует сессию.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/login` | вход по паролю |
| `GET` | `/api/rows?month&year` | таблица месяца с итогами |
| `PATCH` | `/api/workers/:id` | имя, ставка, заметка |
| `GET` | `/api/workers/:id/advances` | авансы сотрудника за месяц |
| `POST` `PATCH` `DELETE` | `/api/advances[/:id]` | работа с авансами |
| `POST` | `/api/sync` | ручная синхронизация месяца (часы + имена) |
| `POST` | `/api/sync/names` | только имена из Google-таблицы |
| `GET` | `/api/sync/check` | проверка токена GIRITON |
| `GET` `PUT` | `/api/settings` | токен, ссылка на таблицу, показатель, интервал |
| `PUT` | `/api/settings/password` | смена пароля |
| `GET` | `/api/export.csv?month&year` | выгрузка |
| `GET` | `/api/cron/sync?key=` | точка для внешнего планировщика |
